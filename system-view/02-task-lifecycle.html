任务生命周期 Task Lifecycle

任务生命周期描述任务从进入内核管理体系开始，其执行资格、 等待条件与运行状态如何随系统事件发生变化。 它连接任务管理与调度机制，是理解多任务运行行为的重要基础。

00

核心定义

Core Concept

任务生命周期是任务在系统中经历的状态变化及其转换条件的集合。 状态用于描述任务当前所处的运行阶段，以及它是否具备被调度执行的条件。

在 HRTOS 中，理解任务生命周期需要同时关注任务状态、 调度规则、等待条件和上下文管理。状态变化可能影响后续执行路径， 但状态本身并不直接代表任务获得了多少处理器时间。

Task lifecycle describes task states, transition conditions, and their interaction with scheduling and execution.
01

任务状态模型

Task State Model

从通用 RTOS 的分析角度，可以使用就绪、运行和阻塞三个基本状态理解任务的调度资格。 这些状态构成概念模型；HRTOS 的实际状态表示与转换规则应以对应版本实现为准。

Ready · 就绪
任务具备运行条件，可以参与调度，但当前未必正在执行。
Running · 运行
任务当前正在使用处理器执行其指令路径。
Blocked · 阻塞
任务正在等待某个条件，例如延时到期、消息到达或资源变为可用。
Other States · 其他状态
创建、挂起、删除或终止等状态是否存在，取决于内核提供的任务管理能力。
这里的 Ready、Running 和 Blocked 是常见的分析术语， 并不意味着 HRTOS 内核一定以同名枚举或独立变量实现这些状态。 对外描述应与真实的内核数据结构和 API 语义保持一致。
02

状态转移关系

State Transitions

任务状态不是固定的线性流程。任务可能在运行期间阻塞， 也可能因时间到期或事件到达重新变为就绪； 被抢占的任务通常仍然具备运行资格，只是暂时让出处理器。

03

就绪状态与调度资格

Readiness & Scheduling

就绪意味着任务满足运行条件，但不意味着任务立即获得处理器。 当多个任务同时就绪时，调度器需要按照内核规定的调度策略选择执行对象。

  • 任务优先级影响调度器对候选任务的选择。
  • 时间片或轮转规则可能影响同一优先级任务的执行顺序。
  • 更高优先级任务就绪后是否立即抢占当前任务，取决于具体调度策略和抢占条件。
  • 中断处理和内核临界区可能影响调度决策实际生效的时刻。

因此，任务状态回答的是“任务是否具备运行资格”， 调度机制回答的是“下一步由谁执行”。

参见 Scheduler Cycle（调度周期）。

04

阻塞、等待与时间推进

Blocking & Time Progression

阻塞表示任务暂时不具备继续运行的条件。 例如任务等待延时到期、等待消息或等待资源。 阻塞期间，该任务通常不会持续占用处理器执行自己的任务代码。

但阻塞不意味着系统时间停止，也不意味着整个系统进入等待状态。 其他就绪任务、中断处理程序和系统时基仍可能继续运行。

  • 时间等待：系统时基推进，达到条件后任务可能重新就绪。
  • 事件等待：消息或指定事件到达后，内核可能解除任务等待。
  • 资源等待：相关资源状态改变后，任务是否可以继续运行取决于同步机制。
Blocking suspends a task's eligibility to execute; it does not freeze system time or stop other tasks from running.
05

运行状态与上下文切换

Running & Context Switching

任务进入运行状态后，处理器执行该任务对应的指令路径。 当发生调度切换时，内核需要依据目标处理器和自身实现， 保存必要的当前上下文，并恢复下一执行对象的上下文。

上下文切换与任务状态变化相关，但二者并非一一对应： 任务可能由运行转为就绪，也可能在内核处理期间发生控制流变化； 而一次调度判断也可能最终继续执行原任务。

  • 上下文切换包含的寄存器和堆栈操作取决于处理器架构及内核设计。
  • 切换开销会影响任务实际可获得的处理器时间。
  • 中断上下文与任务上下文需要分别分析，避免混淆执行边界。

参见 Execution Flow（执行流） 和 Interrupt Flow（中断流）。

06

创建、退出与资源回收

Task Management & Resources

一些 RTOS 提供显式的任务创建、挂起、恢复、删除或终止接口。 这些操作是否存在，以及任务退出后如何回收控制块、堆栈和相关资源， 需要根据具体内核的任务管理能力判断。

对于采用固定任务表或静态任务配置的实现， 任务生命周期可能与支持动态创建和删除任务的系统有所不同。 因此，不应仅依据通用 RTOS 状态图推断 HRTOS 支持动态任务创建或终止。

如果需要描述 HRTOS 4.0 的实际任务生命周期， 应进一步核对任务创建 API、任务控制结构、阻塞与唤醒逻辑、 调度状态表示，以及任务退出或删除机制。
07

生命周期与实时性分析

Lifecycle & Real-Time Analysis

生命周期模型有助于识别任务何时具备运行资格、何时等待条件满足， 以及哪些状态变化可能触发调度。 但状态模型本身不能直接证明任务一定在截止时间前完成。

对具体任务开展实时性分析时，还需要考虑：

  • 任务执行路径的最坏执行时间（WCET）。
  • 高优先级任务和中断造成的执行干扰。
  • 任务等待、资源竞争及同步机制引入的延迟。
  • 调度策略、时间片与上下文切换开销。
  • 任务截止时间及其响应时间的明确计算边界。

生命周期描述任务的状态变化；执行流描述处理器的具体运行路径； 时间分析则评估这些路径在指定条件下是否满足实时约束。

Task states, execution paths, and timing analysis are complementary views of real-time behavior.
∑

语义总结

Key Takeaways

任务生命周期不是单纯的状态名称列表， 而是用于描述任务运行资格、等待条件和状态转换规则的模型。

对 HRTOS 而言，准确理解任务状态与调度机制的关系， 可以帮助开发者分析任务为何运行、为何等待，以及何时可能再次获得处理器。

Task lifecycle modeling clarifies task eligibility, waiting conditions, and the state transitions that influence scheduling.
