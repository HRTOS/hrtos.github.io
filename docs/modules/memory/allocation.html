01

内存空间总览

不同存储空间承担不同职责，地址应分别理解。

BIT
内核状态标志

高速任务启动与删除、调度原因、中断状态、调度模式和临界区状态等位变量。

DATA
直接寻址变量与临时保护区

包括固定地址的中断编号保护、R0 保护以及内核工作变量；另有位于 0x15 的中断嵌套临时变量。

STACK
系统、中断与任务堆栈区域

通过固定地址数组划分系统堆栈保护区、中断堆栈区和用户任务堆栈区。

IDATA
调度与中断现场状态

保存当前任务、上一个任务、调度触发源、时间片、临界区嵌套状态及中断现场数据。

XDATA
内核全局数据与对象池

集中存放任务状态、上下文、SP 记录、任务控制块、统一资源对象和消息队列对象。

地址空间说明： BIT、DATA、IDATA、STACK 所涉及的内部 RAM 地址空间与 XDATA 外部 RAM 不是一条连续地址轴。 本页分别列出各空间的用途；XDATA 统计仅针对指定的 512 字节全局内存池。
02

BIT 状态标志区

以位变量表示内核控制状态。

当前实现使用 volatile bit 定义多项内核状态标志。它们用于高速任务控制、调度判断、中断状态维护和临界区管理。 这些标志不应与普通字节变量或 XDATA 对象混为一谈。

内核标志 · 按当前定义摘录

volatile bit OS_JINCHENG_CUNCHU;

阅读提示： volatile 表示这些对象可能在当前执行路径之外被改变， 编译器需要按相应的易变对象规则处理访问；它本身不等于完整的并发保护机制。

04

堆栈区域

固定地址划分的三段堆栈相关区域。

系统堆栈保护区 0x35 起 · OS_SP_KER 字节
中断堆栈区 0x3A–0x41 · 8 B
用户任务堆栈区域 0x42–0x7F · 62 B
固定地址数组 · 当前定义
unsigned char data OS_HRTOS_DUIZHAN_OS[OS_SP_KER]
    _at_ 0x35;

unsigned char data OS_HRTOS_DUIZHAN_INT[8]
    _at_ 0x3A;

unsigned char data OS_HRTOS_DUIZHAN_APP[62]
    _at_ 0x42;

这三个区域在地址规划上分别承担系统、中断和用户任务相关的堆栈用途。 实际栈深度、安全余量以及调用路径是否可能超出区域边界，需要结合汇编、编译结果和运行时测量验证。

边界核对： 上述系统堆栈数组长度由 OS_SP_KER 决定。 在确认该宏的最终取值前，不应将系统堆栈长度写成固定值。

06

XDATA 全局内存池

以 0x0200 为基地址，通过偏移量组织内核数据。

当前规划的系统全局内存池大小为 512 字节，地址范围是 0x0200–0x03FF。 任务状态、上下文、SP 记录、调度数据及内核对象均在这段 XDATA 中安排固定位置。

全局内存池配置
#define OS_SYS_GLOBAL_BASE  0x0200
#define OS_SYS_GLOBAL_SIZE  512
#define OS_SYS_GLOBAL_END   \
    (OS_SYS_GLOBAL_BASE + OS_SYS_GLOBAL_SIZE - 1)

内核对象区

任务控制块记录任务优先级、状态与等待信息； 统一资源对象承载信号量、互斥锁、事件等资源的状态与等待队列； 消息队列对象则保存缓冲区指针及读写管理信息。

对象 声明大小 当前代码中的地址表达式
OS_TASK 128 B BASE + 0x0125
OS_RES 36 B BASE + 0x01A5
OS_MSGQ 21 B BASE + 0x01C9
发布前必须核对地址映射： 当前提供的对象地址注释写为 OS_TASK @ 0x0336、 OS_RES @ 0x03B6、 OS_MSGQ @ 0x03DA； 但对应的 _at_ (OS_SYS_GLOBAL_BASE + offset) 声明分别计算为 0x0325、 0x03A5 和 0x03C9。 两组地址相差 0x11 字节。这里先明确列出声明表达式，不将两组互相矛盾的地址同时当作最终布局。 正式发布前应以最终编译使用的源文件、链接映射及 HEX 对应版本核实。
07

内存预算与资源占用

固定池大小明确，但最终使用量必须与实际编译布局一致。

当前内存注释声明全局池为 512 字节，规划使用至 0x03EF，剩余 0x03F0–0x03FF 共 16 字节。 不过，由于内核对象地址注释与偏移表达式存在差异， 在完成地址核对之前，不宜将 496 字节使用量视为已经验证的最终编译结果。

原注释规划：496 B 原注释保留：16 B
内存预算的意义： 在资源受限的 8051 平台上，任务数量、上下文长度、资源对象数量和消息队列数量都会影响内核的静态内存占用。 固定地址布局有助于审查分配边界，但不能替代编译器映射检查和运行时栈使用验证。

设计要点

从地址组织理解内核实现，而不是只看内存总量。

固定布局
地址规划可追踪

上下文
任务现场集中管理

标准任务与高速任务使用不同的上下文区域，具体内容由当前上下文保存实现决定。

对象池
统一资源管理模型

任务控制块、统一资源对象与消息队列对象分别存放，支撑调度和 IPC 功能。

验证
布局与实测相互校验

最终地址、对象尺寸、堆栈边界与编译器映射应保持一致，避免注释与实际二进制脱节。
