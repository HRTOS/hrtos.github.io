上下文切换 Context Switch

调度器决定下一个运行的任务，上下文切换则负责完成处理器执行现场的交接。 在资源受限的 8051 平台上，任务栈、寄存器组、内核状态与中断返回路径共同构成 上下文管理的实现基础，也直接影响切换的正确性与实际执行开销。

标准任务 16 个槽位

任务 ID 范围为 0–15，对应标准任务管理结构。

高速任务 2 个槽位

任务 ID 为 16、17，采用独立的高速任务管理路径。

核心职责 保存 · 恢复

维护任务执行连续性，而不只是修改当前任务编号。

Core Concept

保存当前现场，恢复目标现场

任务切换必须维护执行位置、栈状态以及恢复执行所需的处理器状态。 哪些状态需要显式保存、哪些由硬件或其他内核路径处理，取决于具体的切换入口、 寄存器组策略和 HRTOS 内核实现。

Three Responsibilities

调度器 确定接下来运行的任务
上下文管理 维护任务切出与恢复所需的状态
中断机制 遵循中断入口、现场保护与返回规则
01

上下文切换的职责

从调度决策到处理器执行

一个任务不仅包含程序代码，还具有运行过程中的执行位置、栈状态和处理器现场。 当任务暂时离开处理器时，内核必须按照既定规则保留或维护后续恢复所需的信息。 当该任务再次运行时，处理器才能沿着正确的执行路径继续工作。

调度与上下文切换是两个相互关联但职责不同的环节。 调度器依据任务状态和调度策略确定运行对象；上下文切换则负责完成执行现场的交接。 调度决策正确，并不自动意味着现场保存与恢复也一定正确。

核心区别

调度解决“谁接下来运行”，上下文管理解决“目标任务如何正确继续执行”。 分析实时响应时，还需要进一步考虑触发事件、内核临界区、中断影响和具体执行路径。

任务上下文涉及的状态

状态类别 主要作用 实现注意点
执行位置 确定任务恢复后的执行位置。 返回地址及其处理方式与具体控制流有关。
栈状态 维持函数调用、返回过程和栈数据。 必须遵循 8051 堆栈规则与编译器约定。
处理器现场 保存后续执行所需的处理器状态。 保存范围取决于切换路径和寄存器组策略。
任务记录 关联任务身份、状态及上下文管理信息。 内核记录不一定与处理器现场存放在同一区域。
02

HRTOS 上下文管理结构

标准任务、高速任务与栈指针记录

HRTOS 将标准任务与高速任务的相关管理信息分开组织。 阅读内核结构时，需要区分栈指针记录、上下文管理区域和任务状态记录： 它们彼此关联，但承担的职责并不相同。

Standard Tasks

OS_JINCHENG_SP OS_TASK_CONTEXT

标准任务的栈指针记录与上下文管理区域。 当前布局分别为 16 字节和 208 字节。

Fast Tasks

高速任务

OS_KUAI_SP OS_FAST_CONTEXT

高速任务的栈指针记录与上下文管理区域。 当前布局分别为 2 字节和 10 字节。

如何理解这些尺寸

上述数字对应当前 HRTOS 4.0 内存布局中的区域占用。 它们描述的是结构区域大小，不应直接理解为每次切换的实际搬运字节数。 保存字段、具体顺序和执行路径仍应以对应版本的内核定义及汇编产物为准。

04

标准任务的上下文管理

维持任务执行连续性

标准任务需要维护各自独立的执行过程。任务被切出时，内核需要保留恢复该任务所需的状态； 当任务再次成为运行对象时，则沿对应恢复路径重新建立执行环境。

STANDARD TASK CONTEXT CONCEPTUAL VIEW 
OS_JINCHENG_SP
    └── 标准任务栈指针记录

OS_TASK_CONTEXT
    └── 标准任务上下文管理区域

任务切出
    └── 维护后续恢复所需的状态

任务恢复
    └── 恢复目标任务的执行环境

从运行到恢复

  1. 任务运行：处理器执行当前任务指令，栈和相关状态持续变化。
  2. 进入内核路径：系统根据对应事件和调度规则进入内核处理流程。
  3. 维护当前现场：按照具体实现保存或记录后续恢复所需的状态。
  4. 确定目标任务：内核根据调度结果确定下一个运行对象。
  5. 恢复目标现场：按照目标任务的上下文管理规则恢复执行所需状态。
  6. 继续执行：处理器转入目标任务对应的执行路径。
8051 平台的实现边界

8051 的堆栈操作、返回地址、工作寄存器组和编译器调用约定， 与通用 32 位或 64 位处理器并不相同。 不能仅凭通用 RTOS 的上下文模型推断 HRTOS 的精确保存顺序和栈帧大小。

05

高速任务与寄存器组

利用 8051 硬件资源优化关键路径

8051 的工作寄存器组为内核设计提供了可利用的硬件资源。 在适当的寄存器组分配和现场管理策略下，可以减少某些执行路径中不必要的寄存器保存与恢复操作。

FAST TASK CONTEXT CONCEPTUAL VIEW 
OS_KUAI_SP
    └── 高速任务栈指针记录

OS_FAST_CONTEXT
    └── 高速任务上下文管理区域

寄存器组策略
    └── 配合切换路径管理处理器现场

寄存器组优化的价值与边界

  • 减少部分现场搬运：合理利用硬件寄存器组，可能减少特定路径上的保存与恢复指令。
  • 控制切换开销：缩短关键路径，有助于降低对应场景的执行成本。
  • 维护完整状态：执行位置、栈状态及其他必要现场仍需得到正确管理。
  • 遵守资源约定：任务、中断和其他执行路径必须遵循一致的寄存器组使用规则。
硬件优化不等于零开销切换

专用寄存器组只能优化适用的部分路径，不能单独证明任务切换没有额外开销。 实际收益需要结合汇编指令、寄存器组使用方式和目标 MCU 的时序测量来评估。

06

上下文切换的执行关系

理解关键环节，而不是假定固定汇编顺序

从职责上看，一次任务切换涉及当前现场管理、目标任务确定以及目标现场恢复。 以下示意用于解释这些环节的关系，不代表所有 HRTOS 切换路径都严格采用相同顺序。

当前任务运行 处理器执行当前任务
↓
进入内核处理路径 由相应的系统事件或调度流程触发
↓
维护当前任务现场 保存或记录恢复所需的状态
↓
确定目标任务 按照当前调度规则选择运行对象
↓
恢复目标任务现场 恢复目标任务的执行环境
转入目标执行路径 继续执行相应任务代码

概念流程示意。实际入口、保存顺序、调度位置和返回方式应以 HRTOS 对应版本的实现为准。

切换触发与调度结果不是同一概念

任务主动让出处理器、任务状态变化以及系统调度过程，都可能与执行对象改变有关。 但某个事件是否立即导致任务切换，取决于 HRTOS 的调度模式、当前运行状态和具体处理路径。

分析时应分别确认：什么事件触发内核处理、调度器如何确定目标任务、内核通过什么路径完成现场交接。 这样更容易区分调度行为问题与上下文管理问题。

07

任务上下文与中断现场

共享处理器资源，但具有不同的执行约束

任务与中断共享处理器资源，但二者的进入方式、执行目标和返回要求并不相同。 在 8051 上，中断现场保护还受到硬件堆栈、寄存器组和嵌套中断规则的约束。 因此，任务上下文管理必须与中断机制协同设计。

机制 主要职责 分析重点
Task Context 管理任务切出和恢复所需的执行状态。 任务栈、现场保存和恢复路径。
Interrupt Context 满足中断执行及中断返回的现场要求。 中断入口、寄存器保护和返回规则。
Scheduler 依据调度规则确定任务执行对象。 调度条件、运行状态及切换时机。

中断退出路径

HRTOS 的中断入口与退出由内核对应路径管理。对于通过跳转进入的特定中断处理路径， 不能直接套用普通 C 函数调用和返回的假设。

INTERRUPT EXIT KERNEL API 
os_interrupt_exit()

用于 HRTOS 对应中断处理路径的退出管理。
具体调用位置、现场要求及后续返回行为，
必须遵循当前内核版本的中断接口约定。
对实时分析的意义

只有明确区分任务切换路径与中断处理路径，才能合理分析任务切换耗时、 中断响应时间、嵌套中断开销，以及中断对关键代码执行时间的影响。

08

切换开销与时序验证

从内核实现走向可复核的工程数据

上下文切换开销不仅取决于保存和恢复现场所需的指令。 内核入口、任务状态维护、调度处理以及返回目标任务的路径， 都可能影响最终的执行时间。

影响切换成本的因素

  • 现场范围：具体路径需要保存和恢复多少状态。
  • 栈操作：栈指针与堆栈内容的维护方式。
  • 寄存器组策略：硬件资源能否减少必要的现场搬运。
  • 调度处理：任务选择和运行状态更新带来的额外指令。
  • 中断影响：测量窗口内是否发生中断及嵌套处理。
  • 编译产物：编译器生成代码、手写汇编和具体分支路径。

建议的验证方法

  1. 明确目标 MCU、时钟频率、编译器版本和编译配置。
  2. 确定测量边界，区分纯现场交接、完整任务切换和包含中断的场景。
  3. 检查生成的汇编代码，识别关键路径、分支和指令周期。
  4. 使用 GPIO、逻辑分析仪或示波器测量目标芯片上的实际执行时间。
  5. 分别记录不同切换路径的结果，不以单次平均值替代最坏路径分析。
实测时间不等于最坏执行时间上限

一条路径的实测时间不能直接代表所有切换场景的统一上限。 如果要给出最坏执行时间结论，还需要明确分析范围、覆盖条件、路径边界和中断干扰假设， 并对关键路径进行可复核的指令级分析。

09

内核分析与故障排查

从结构定义到执行结果逐层验证

当任务恢复异常、栈状态错误或切换时序与预期不一致时， 可以从以下方向逐步缩小问题范围。

  • 确认当前任务与目标任务是否符合预期。
  • 检查任务栈指针的保存与恢复是否一致。
  • 核对现场保存范围与恢复路径。
  • 检查寄存器组分配和使用约定。
  • 区分普通任务路径与中断路径。
  • 检查嵌套中断和中断退出路径的约束。
  • 核对编译生成的汇编指令和链接映射文件。
  • 记录测量条件，保证测试结果能够复现。

以上清单用于组织排查工作，并不意味着每次故障都由这些问题共同导致。 应结合实际故障现象、内核实现和测量证据逐项验证。

本页要点

  • 调度器决定运行对象，上下文切换负责执行现场交接。
  • 标准任务与高速任务使用不同的上下文管理区域。
  • 栈指针记录、上下文区域和任务状态记录是相关但不同的内核资源。
  • 当前 4.0 布局中，标准任务上下文区域为 208 字节，高速任务上下文区域为 10 字节。
  • 任务现场与中断现场必须遵循各自的保护和返回规则。
  • 切换开销及实时性结论应由实际内核路径、汇编分析和目标芯片测量支持。
