资源竞争 Resource Contention

资源竞争描述多个任务、中断或执行路径在共享处理器时间、 数据对象或同步资源时产生的等待、干扰与执行顺序约束。 对实时系统而言，关键不只是减少竞争，更是识别竞争来源、 限定其影响范围，并判断它对响应时间和截止期限的影响。

Execution Interference Blocking Time Timing Analysis
01 / DEFINITION

资源竞争的核心问题

当多个执行主体依赖同一资源时，它们的执行时间线可能发生耦合。 竞争会带来等待或干扰，但是否破坏实时性，取决于这些影响能否被正确约束和分析。

FACTOR / 01

竞争来源

识别处理器执行权、中断处理时间、共享数据和同步资源等竞争来源。

FACTOR / 02

时间影响

确定额外执行、等待、阻塞或中断干扰如何改变任务响应时间。

FACTOR / 03

可分析边界

通过调度规则、临界区约束、资源上限与测量分析建立可验证的时间边界。

02 / CONTENTION TYPES

主要竞争类型

对 8051 等资源受限微控制器，优先关注处理器执行权、中断与共享状态。 其他平台特有的总线或 DMA 竞争，则应按目标硬件实际情况纳入分析。

CPU

处理器执行权竞争

多个就绪任务竞争有限的处理器时间。优先级、抢占策略、时间片与调度开销， 共同决定任务何时获得执行机会。

关注：就绪任务、调度策略、执行时间与响应时间。
ISR

中断执行干扰

中断处理会占用处理器时间，并可能延迟当前任务或内核路径。 中断优先级、嵌套规则与处理时长决定其对任务执行的影响。

关注：中断响应、嵌套层级、现场保存与中断执行时间。
LOCK

共享资源与临界区

多个执行主体访问共享数据时，可能需要临界区或同步保护。 保护范围过大可能增加等待时间或延长中断屏蔽时间。

关注：共享对象、保护范围、同步开销与数据一致性。
MEM

内存与资源容量约束

有限 RAM、固定容量队列和资源池会限制系统可同时容纳的对象数量。 资源不足可能导致申请失败或改变应用的运行路径。

关注：内存占用、对象上限、分配成本与失败处理。
03 / TIMING INTERACTION

竞争如何改变任务时间线？

竞争对时间的影响通常可以从额外执行、等待和阻塞三个方向分析。 具体路径取决于任务优先级、中断行为与同步机制。

执行干扰
其他执行路径占用处理器

例如中断处理或更高优先级任务执行，使当前任务的连续执行时间被打断。

资源等待
当前任务无法立即使用所需资源

例如等待共享资源释放、消息到达或同步条件满足，任务可能进入阻塞状态。

延迟传递
上游延迟影响后续工作

如果后续任务依赖当前任务提供的数据或服务，上游延迟可能传递到下游， 但是否累积或放大，需要依据实际依赖关系分析。

期限评估
判断任务能否在截止期限前完成

将执行时间、调度干扰、阻塞与其他相关开销纳入响应时间评估， 检查任务是否满足其时限要求。

04 / ANALYSIS MODEL

竞争与响应时间分析

资源竞争需要落实到具体的时间项。下列关系用于建立分析思路， 并非适用于所有调度策略的完整响应时间公式。

响应时间 = 执行时间 + 干扰时间 + 阻塞时间 + 其他相关开销

这是概念性分解。各项的定义、是否存在重叠，以及如何计算， 必须根据实际调度算法、中断模型和资源协议确定，避免重复计入。

时间项 主要来源 分析重点
执行时间 任务本身完成工作所需的处理器时间。 代码路径、输入条件、目标频率及最坏执行路径。
执行干扰 高优先级任务或中断处理占用处理器。 触发频率、执行上界、优先级与嵌套关系。
资源阻塞 等待共享资源、临界区或同步条件。 最大阻塞时长、资源访问顺序及潜在死锁条件。
系统开销 调度、上下文切换、计时与相关内核处理。 实际调用路径、测量结果及是否已包含在其他时间项中。
05 / CONTROL STRATEGIES

控制竞争影响的工程方法

目标不是完全消除系统中的所有竞争，而是让关键竞争有明确的规则、 可控的范围和可验证的最坏情况。

  • 01
    明确调度策略与优先级关系

    明确哪些任务能够抢占其他任务、时间片如何分配，以及中断与任务执行之间的关系。

  • 02
    限制临界区范围

    只保护确实需要原子性或一致性的操作，避免在保护区中执行不必要的等待或长耗时处理。

  • 03
    约束共享资源访问协议

    明确资源获取与释放规则、访问顺序和失败路径；使用互斥或同步机制时， 还需考虑优先级反转和阻塞时间。

  • 04
    限制资源容量并定义失败行为

    为队列、资源池和其他有限资源设置上限，并明确资源耗尽时的返回值、恢复策略或降级行为。

  • 05
    测量并验证关键时间路径

    结合 GPIO 测量、反汇编、压力测试与最坏情况分析，验证调度、中断和资源访问的实际时间边界。

06 / DETERMINISM

资源竞争与确定性

确定性并不意味着每次执行都必须耗时完全相同， 而是系统的关键行为及其时间边界能够在明确的假设下得到分析和验证。

CASE / A

竞争有界

竞争来源、资源协议和最大阻塞时间明确，可以将相关影响纳入响应时间分析。

CASE / B

竞争缺乏约束

例如临界区过长、资源等待没有明确上限或共享访问协议不清晰， 会使响应时间更难分析。

CASE / C

通过验证建立证据

使用实现审查、测量和必要的最坏情况分析，验证关键路径是否满足指定时限。

!

避免把风险等同于结论

资源竞争可能增加延迟和分析难度，但并不必然导致系统失去确定性。 同样，压力测试中未观察到超时，也不能单独证明所有运行条件下的最坏执行时间都有界。 实时性结论应建立在明确的系统假设、实现细节和验证证据之上。
