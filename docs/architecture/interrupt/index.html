中断架构 Interrupt Model & Response Path

中断是嵌入式实时系统响应外部事件的重要机制。 本模块围绕 HRTOS 的中断模型、处理流程与响应延迟展开， 并重点区分中断处理、调度决策和任务上下文切换之间的关系。

01 / Overview

中断架构概览

从中断机制的基本组成入手，建立对事件响应过程及其系统影响的整体认识。

中断机制关注什么？

在 8051 系统中，中断响应不仅涉及处理器对中断请求的响应， 还涉及中断服务程序的执行，以及中断处理与系统运行状态之间的关系。

对 RTOS 而言，还需要进一步分析中断处理是否引起调度请求、 调度决策何时发生，以及任务上下文在何时保存和恢复。 这些阶段彼此相关，但不应直接视为同一个操作。

本模块的三个主题

  • 01 中断流程：关注处理阶段及其与任务运行的关系。
  • 02 中断延迟：关注延迟定义、影响因素与测量方法。
  • 03 中断模型：关注中断机制的组成与组织方式。
重要区分： 中断响应时间、ISR 执行时间和中断退出后的任务切换时间是不同的分析对象。 具体测量边界与处理顺序应以目标芯片、HRTOS 实现和测试方法为准。

03 / Analysis Principles

理解中断机制的关键原则

分析中断系统时，需要把处理器行为、内核机制与实测结果区分开来。

明确时间边界

说明延迟从哪个事件开始、到哪个事件结束。 不同测量边界得到的结果不能直接混为一谈。

区分中断与调度

ISR 执行、中断退出、调度器选择任务和上下文切换 可能发生关联，但各自具有不同的职责。

结合目标平台

中断行为与 8051 内核、芯片扩展、编译器生成代码及系统配置有关。 分析结论应明确对应的目标环境。

以实现和测量为依据

中断嵌套条件、临界区影响与响应时间上限， 应通过实际代码、编译结果和测试数据进行确认。
