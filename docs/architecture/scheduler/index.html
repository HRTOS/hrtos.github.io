调度器架构 Scheduler Architecture

调度器连接任务优先级、运行时任务选择与时间约束。 本模块从优先级控制、调度执行模型和可调度性理论三个层面， 梳理 HRTOS 的任务调度机制及其与系统实时行为之间的关系。

01

模块概述

从执行权分配到实时约束分析，建立完整的调度认知。

在 RTOS 中，任务调度决定就绪任务如何竞争处理器执行权。 调度行为不仅取决于任务优先级，还受到任务状态、调度触发条件、 中断活动以及内核执行规则的共同影响。 因此，理解调度器需要同时区分“谁更有资格运行”“系统何时重新选择任务” 和“给定约束是否能够满足”这三个不同问题。

01 / PRIORITY

执行权如何分配

通过优先级规则表达任务之间的执行权关系，并明确抢占与优先级变化的语义。

02 / DECISION

何时选择下一个任务

根据任务状态和调度触发条件执行任务选择，确定运行时的切换行为。

03 / ANALYSIS

时间约束能否满足

结合执行时间、干扰、阻塞和调度开销，分析任务响应时间及可调度性边界。

04

调度器的职责边界

调度是实时行为的重要组成部分，但不是唯一决定因素。

调度器关注什么

任务选择规则、优先级关系、调度时机与执行权转换。 这些机制决定了任务在竞争处理器时如何获得执行机会， 以及系统在满足触发条件后如何进行调度决策。

系统实时性还取决于什么

中断延迟、临界区长度、上下文切换开销、资源阻塞与任务执行时间。 即使调度规则正确，如果这些因素缺乏约束或测量依据， 也不能仅凭调度策略就推导出端到端的实时保证。

工程判断： 优先级规则清晰，不代表所有任务必然满足截止期限； 压力测试长期通过，也不等于已经证明最坏情况下的响应时间上界。 对实时性作出结论时，应明确分析假设、测量条件、系统开销及尚未覆盖的边界情况。
