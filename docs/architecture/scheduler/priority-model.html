优先级模型 Priority Model

优先级用于表达不同执行实体之间的执行权关系。 在 HRTOS 中，理解优先级不仅要看数值高低，还需要区分普通任务、 快速任务与中断执行层级，并结合具体调度规则判断实际的执行行为。

Priority Hierarchy Task Preemption 8051 Context Control
01

优先级层级

从空闲任务、普通任务到快速任务和中断执行层级。

HRTOS 使用 0–10 的优先级语义描述不同执行层级。 普通任务与快速任务属于任务执行域；中断处理及嵌套中断则涉及独立的中断控制路径。 因此，层级数值不能简单理解为所有执行实体都由同一个任务选择器统一排序。

HRTOS 优先级层级示意 数值越高，优先级语义越高
10

嵌套中断层级

对应更高层级的嵌套中断处理路径，实际行为受中断控制规则约束。

中断控制
9

中断执行层级

用于描述中断处理相关的执行层级；不能直接等同于普通任务优先级。

ISR 路径
8

快速任务层级

快速任务执行域，独立于普通任务的任务编号与常规任务寄存器组安排。

快速任务
1–7

普通任务层级

普通任务的优先级范围；实际运行顺序还取决于调度模式、就绪状态和切换条件。

普通任务
0

空闲层级

空闲任务层级，在没有更高优先级的可运行任务时承担空闲执行职责。

Idle

阅读说明： 此处展示的是 HRTOS 的优先级语义层次，不是对 CPU 执行顺序的绝对保证。 中断是否能够嵌套、何时允许任务切换，以及快速任务与普通任务之间如何交接， 仍需结合中断架构和调度模型理解。

02

优先级的语义

优先级是调度规则的一部分，不等于完整的实时性评价。

EXECUTION ORDER

执行权关系

优先级用于决定多个可运行任务之间的相对执行权。 在抢占式调度条件满足时，更高优先级任务可以获得优先执行机会； 具体何时切换取决于 HRTOS 的调度触发与内核控制规则。

RUNTIME STATE

配置与运行状态

任务配置优先级、运行时有效优先级和当前是否具备运行条件， 是需要分别理解的概念。任务被阻塞、挂起或等待资源时， 仅凭优先级数值无法判断它是否会立即执行。

运行决策 = f（优先级，任务状态，调度模式，切换条件）

这是用于理解调度因素的概念表达式，并非 HRTOS 内核中的实际计算公式。 截止期限、执行时间、资源阻塞和系统负载主要用于任务设计与实时性分析， 不应未经实现依据就视为内核动态计算优先级的输入。

03

优先级与调度机制

优先级决定相对执行权，调度机制决定执行权如何落实。

机制 解决的问题 理解时需要注意
优先级抢占 更高优先级任务就绪时，何时能够获得执行机会。 需要考虑切换触发条件、中断状态与内核临界区。
时间片调度 符合相应调度条件的任务如何分配执行时间。 时间片规则与优先级抢占规则并非同一概念。
快速任务机制 为特定任务提供不同于普通任务的执行路径。 需要结合快速任务的上下文保存和切换机制分析。
中断嵌套 允许满足条件的更高层级中断打断当前中断处理。 受硬件中断能力、屏蔽状态和软件处理规则共同约束。
重要区别： 优先级继承是一种用于处理特定优先级反转问题的同步协议， 不是所有 RTOS 都会自动具备的通用能力。 在没有确认 HRTOS 对应的互斥资源协议及其实现前， 不应将优先级继承描述为内核已经提供的功能。
04

优先级设计原则

优先级配置应服务于可分析的执行需求，而不是单纯划分任务重要程度。

01 / REQUIREMENTS

从响应需求出发

根据任务的响应需求、截止期限、执行频率和依赖关系设计优先级。 业务重要性可以作为设计因素，但不能替代对时间约束的分析。

02 / INTERFERENCE

控制高优先级干扰

过多的高优先级工作可能增加低优先级任务的等待时间。 需要评估高优先级任务的执行频率、执行时长及其对其他任务的影响。

03 / BLOCKING

明确资源阻塞

任务等待共享资源或进入临界区，可能使实际响应时间偏离仅根据优先级作出的判断。 应明确阻塞来源与持续时间。

04 / VALIDATION

验证实际执行路径

结合反汇编、时序测量、最坏情况分析和压力测试检查调度行为。 不同验证手段的覆盖范围不同，应明确各自能够支持的结论。

05

优先级与实时性边界

高优先级意味着执行权优势，不意味着无条件的响应时间保证。

任务的实际响应时间由执行时间、调度干扰、资源阻塞、中断活动以及系统开销等因素共同影响。 即使任务具有较高优先级，也可能受到中断屏蔽、不可抢占区间或其他执行约束影响。 因此，优先级配置是实时系统设计的重要基础，但不能单独作为满足截止期限的证明。

工程结论： 优先级模型定义任务执行权的相对关系；调度模型说明内核如何选择和切换任务； 实时性分析则需要在明确假设和开销边界的基础上，评估任务响应时间是否满足要求。 三者相互关联，但不能相互替代。
