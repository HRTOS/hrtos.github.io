内核结构 Kernel Structure & Layer Model

01

结构概述

内核不是孤立的函数集合，而是围绕 CPU 执行权组织起来的控制机制。

HRTOS 内核负责协调任务状态、调度决策、中断事件和上下文切换。 这些机制共同决定哪个任务能够运行、何时转移执行权，以及系统如何从事件处理过程恢复到正常任务执行。

为便于分析，可以从调度决策、执行控制、中断处理和任务间通信 四个功能领域理解内核。它们是用于解释系统职责的架构视图，并不意味着每个领域都对应一个独立的软件模块， 也不意味着所有事件都必须按同一条固定路径执行。

03

内核控制关系

用统一的视角理解事件、状态变化、调度决策与任务执行之间的关系。

下图是概念性的控制关系，不代表所有内核操作都必须完整经过每一个阶段。

事件与状态变化 中断、系统调用、任务状态变化
内核控制入口 进入相应的内核处理路径
调度决策 评估任务状态与调度规则
执行权转移 按需进行上下文切换
任务运行 执行任务代码或继续原任务
任务状态更新 就绪、运行、等待等状态变化
等待或事件响应 任务继续、阻塞或等待后续事件
后续内核处理 根据新的状态与事件继续运行
关键关系 事件可能触发内核处理，但不一定导致任务切换；任务状态变化可能影响调度结果， 而调度决策只有在需要改变执行对象时，才需要进行相应的上下文切换。
04

结构设计关注点

评价内核结构，重点在于控制路径是否清晰、执行边界是否明确。

01 / CONTROL

控制入口清晰

调度触发条件、内核处理入口与任务恢复路径应具有明确的语义， 便于分析任务何时可能发生切换。

02 / CONTEXT

执行现场可管理

上下文保存与恢复必须遵循一致的规则，并与处理器寄存器、任务栈和中断机制协调。

03 / STATE

任务状态可追踪

任务的运行、就绪和等待等状态应与调度条件相匹配， 避免状态管理与实际执行行为发生冲突。

04 / INTERRUPT

中断边界明确

中断服务、嵌套处理与任务调度之间需要明确的约束， 以便分析中断响应和执行权转移的实际路径。

05 / RESOURCE

资源开销可核算

在 8051 等资源受限平台上，代码空间、内部 RAM、外部 RAM、栈空间和执行时间都需要纳入设计评估。

06 / ANALYSIS

执行路径可验证

对关键调度和中断路径进行测量与分析，为响应时间、切换开销及资源使用情况提供依据。

05

架构边界与系统本质

功能分层是分析工具，实际运行由具体内核路径和处理器机制共同决定。

调度器负责作出调度决策，上下文管理机制负责保存和恢复执行现场， 中断机制负责响应硬件事件，而通信与同步机制则影响任务之间的协作关系。 这些职责相互关联，但不应在概念上混为一谈。

对 HRTOS 这样的 8051 实时系统而言，内核结构还必须考虑处理器寄存器组织、 中断优先级、任务栈开销以及有限的 RAM 资源。 架构设计不仅要回答“哪个任务运行”，也要能够解释“执行权如何转移”以及“这一过程付出了多少时间与空间成本”。

理解重点： 实时性并不单由调度算法决定。中断响应、临界区长度、上下文切换成本、 任务状态管理和资源竞争都会影响系统的实际响应表现。 对具体实时性指标的判断，应以明确的测试条件、测量数据和分析结果为依据。
