HRTOS / KERNEL ARCHITECTURE

内核架构 Kernel Architecture

内核是 HRTOS 的执行控制核心。它围绕任务上下文、中断处理、调度决策与系统状态管理， 组织处理器执行权的分配和转移，使应用任务能够在明确的内核规则下协同运行。 本页面从系统层面介绍内核的职责边界、控制模型与内部架构入口。

01 / CORE

内核的系统定位

System Role & Responsibility

从任务管理到执行权控制

HRTOS 内核不仅需要记录任务状态、选择待运行任务，还需要协调中断处理与任务上下文的保存、恢复和切换。 这些机制共同决定了处理器在不同执行主体之间如何转移控制权。

对于资源受限的 8051 平台，寄存器组织、内部数据存储空间、中断入口以及编译器生成的代码都会影响内核设计。 因此，内核架构必须同时考虑执行行为、资源占用和底层处理器约束。

Architectural Principle 明确执行规则，控制状态转换，约束执行权转移。

架构层描述职责与关系；具体时序和资源开销应以对应实现及测试结果为准。

02 / SCOPE

内核的核心职责

Kernel Responsibility Domains

DOMAIN / 01

执行上下文

管理任务执行所需的上下文信息，并在符合内核规则的情况下保存和恢复处理器状态， 为任务切换提供底层基础。

DOMAIN / 02

调度与执行权

根据任务状态、优先级和调度策略确定后续执行主体，并协调事件发生后的调度判定与任务切换。

DOMAIN / 03

中断与状态协调

协调中断处理、内核执行与任务恢复之间的关系，使异步事件能够按照既定控制路径影响系统执行。

03 / MODEL

内核执行控制模型

Event-Driven Execution Control

当中断、任务状态变化或其他内核事件发生时，系统需要根据当前执行环境和调度规则， 决定是否继续当前执行路径，或者将执行权交给其他任务。

事件触发 中断、延时到期或状态变化
内核判定 检查执行条件与调度规则
执行权处理 继续运行或切换上下文
状态更新 进入新的执行阶段
阅读提示 以上为概念层控制模型，并不表示所有事件都会引起任务切换。 实际路径取决于事件类型、当前运行环境、调度策略以及具体内核实现。

05 / BOUNDARY

内核边界与平台约束

Kernel Responsibilities & Hardware Constraints

内核负责协调
  • 任务状态与可运行条件的管理
  • 调度策略与执行主体的选择
  • 任务上下文的保存、恢复与切换
  • 中断处理与任务执行之间的衔接
  • 内核对象和受控资源的管理机制
实现受到约束
  • 8051 寄存器组及处理器执行模型
  • DATA、IDATA、XDATA 等存储空间限制
  • 中断优先级、入口与返回路径
  • 编译器调用约定和生成代码特征
  • 实际运行时的时延、栈空间与资源开销

注：上述内容用于说明架构分析维度。具体支持范围、资源占用及实时性能，应以对应版本的实现、配置和测试数据为依据。
