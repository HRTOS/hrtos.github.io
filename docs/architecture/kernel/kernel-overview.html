HRTOS / KERNEL OVERVIEW

内核架构总览 Kernel Architecture Overview

HRTOS 内核是系统执行控制的核心，围绕任务调度、上下文管理、中断处理与资源约束， 建立处理器执行行为和任务运行状态之间的联系。 本页面从架构层面介绍内核的职责、主要控制域及其与系统其他模块的关系。

8051 Native Kernel Core Execution Control Real-Time Scheduling
01 / ROLE

内核的系统定位

SYSTEM ROLE & ARCHITECTURAL RESPONSIBILITY

连接处理器机制与任务执行

内核负责组织任务的运行状态、调度决策和上下文管理，并协调中断处理与任务执行之间的衔接。 它决定系统如何根据任务状态和调度规则安排处理器执行权。

在 8051 这样的资源受限平台上，内核还必须考虑寄存器组织、内部数据存储空间、 堆栈使用、中断入口和编译器调用约定等底层条件。 这些约束会直接影响内核机制的设计和实现方式。

CORE PRINCIPLE 让任务状态、调度规则与处理器执行机制协同工作。

架构说明负责解释职责与关系；具体实现细节应以对应版本的源码和技术文档为准。

02 / SCOPE

内核核心职责

CORE RESPONSIBILITY DOMAINS

内核的职责并非孤立的功能列表，而是共同构成系统执行控制的几个方面。

DOMAIN / 01

任务与调度

管理任务运行状态，依据系统采用的调度策略确定可运行任务的执行安排。

DOMAIN / 02

上下文管理

协调任务执行状态的保存、恢复与切换，为处理器在不同任务之间转移执行权提供基础。

DOMAIN / 03

中断控制

协调中断处理与任务执行之间的关系，管理相关入口、退出及可能发生的调度衔接。

DOMAIN / 04

内核资源管理

管理内核使用的任务控制信息、同步通信对象及其他受配置约束的资源。

DOMAIN / 05

执行状态协调

协调任务状态变化、事件处理和调度条件，确保不同执行阶段之间遵循内核规则。

DOMAIN / 06

平台适配约束

在处理器架构、编译器约定和有限存储空间的约束下组织底层执行机制。

04 / EXECUTION

内核执行控制的基本关系

EXECUTION CONTROL MODEL

当系统发生相关事件时，内核可能需要更新任务状态、重新评估调度条件， 并根据处理结果继续原执行路径或切换到其他任务。

STAGE / 01

事件或请求

中断、系统 API、时间事件或任务状态变化。

STAGE / 02

处理与状态更新

执行对应处理逻辑，更新必要的系统或任务状态。

STAGE / 03

调度判定

在适用的执行路径中，依据调度规则判断后续执行安排。

STAGE / 04

继续或切换

继续当前路径，或者通过相应机制转移任务执行权。

重要说明： 并非所有事件都会进入相同的调度路径，也并非所有调度判定都会导致任务切换。 具体控制流程取决于事件类型、执行环境及 HRTOS 的实际实现。
05 / BOUNDARY

内核与其他系统模块的关系

KERNEL & SYSTEM BOUNDARIES

内核关注
  • 任务状态及可运行条件
  • 调度规则与执行权转移
  • 上下文保存和恢复机制
  • 中断与任务执行的协调
  • 内核对象和资源使用约束
系统其他模块关注
  • IPC 提供的通信与同步能力
  • 任务模块提供的任务管理接口
  • 驱动和 HAL 提供的硬件访问能力
  • Shell、Modbus 等上层功能
  • 应用自身的业务逻辑与执行流程
以上是概念职责划分。实际模块边界、API 归属与调用关系，应以 HRTOS 对应版本的接口和实现为准。
